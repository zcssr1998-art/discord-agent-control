# Discord 远程 Agent 控制台：开发任务书

## 最终目标

把 iPhone 上的 Discord 变成 Windows 开发机的远程 Agent 控制台：

**iPhone Discord 发需求 → Windows 上现有的 Claude Code + DeepSeek 4.1 Flash 真执行 → Discord 实时看进度 → 高风险操作手机审批 → 最终结果回 Discord。**

Codex Plus 不是必经流程。DeepSeek 能完成就不切 Codex；只有 DeepSeek 明确失败、卡死、兼容性问题或用户主动要求时，才升级 Codex。

ChatGPT 在线聊天负责：需求拆解、架构、研究、代码审查、疑难问题、生成给 Agent 的任务包。由于 Plus 在线聊天不是可被 Discord 外部直接调用的 API，V1 不做浏览器自动化劫持；需要 ChatGPT 时生成紧凑 handoff，由用户粘贴给 ChatGPT。

## 已有环境，禁止重复搭建

- Windows 已安装 Claude Code 2.1.270。
- 已经跑通 Claude Code → DeepSeek Anthropic 兼容接口。
- 当前环境变量已有：
  - `ANTHROPIC_BASE_URL=https://api.deepseek.com/anthropic`
  - `ANTHROPIC_MODEL=deepseek-flash[1m]`
  - `CLAUDE_CODE_EFFORT_LEVEL=max`
  - `CLAUDE_CODE_AUTO_COMPACT_WINDOW=786432`
- 已知 Claude 命令位于用户 npm 目录，正常情况下直接使用 `claude` 即可，Bridge 必须继承现有用户环境，不重新维护第二套 DeepSeek 配置。
- Codex 已有 ChatGPT Plus 登录额度，但首版不要求接入。

## 当前代码基线

不要从零重写。直接接管本项目：

- `src/claude-runner.mjs`：持久 Claude Code 进程、stream-json 输入输出、session resume。
- `src/discord-ui.mjs`：Discord 消息、实时进度、审批按钮。
- `src/policy.mjs`：工具风险分类。
- `src/hook-server.mjs`：本地审批服务。
- `scripts/approval-hook.mjs`：Claude `PreToolUse` fail-closed Hook 客户端。
- `scripts/install-global-hook.ps1`：安装全局 Hook，但仅 `DISCORD_BRIDGE_ACTIVE=1` 时生效，因此普通本地/WebUI Claude Code 不受影响。
- `tests/`：现有核心测试，不允许为了过测试删除或弱化。

## V1 验收标准

必须在真实 Windows 主机完成以下闭环，才算 V1 完成：

1. iPhone Discord 给 Bot 发普通自然语言任务。
2. Bridge 在绑定目录启动/复用现有 DeepSeek-backed Claude Code。
3. Agent 能真实读取、编辑文件并执行测试。
4. Discord 持续显示工具调用/进度，但避免逐 token 刷屏。
5. `Read/Glob/Grep`、工作区内普通 Edit/Write、测试/构建命令默认自动通过。
6. `.env/凭据/SSH key`、工作区外写入、网络安装/发布、`git push`、删除/重置等高风险操作必须暂停。
7. 手机上收到 `Allow once / Allow session / Deny` 三个按钮。
8. 手机选择后，原 Claude tool call 必须继续或被拒绝；不能只是假 UI。
9. `!status`、`!cwd <绝对路径>`、`!stop`、`!reset` 可用。
10. 只有配置的 Discord Owner ID 可以发任务和审批。
11. Bridge/审批服务异常时，Bridge 会话必须 fail-closed，不能因为审批服务掉线就放行危险操作。
12. 普通本地 Claude Code/WebUI 不应因为安装 Hook 而被 Discord Bridge 干扰。

## 技术路线

### Discord 层

使用 `discord.js`，Gateway 长连接，不需要公网 IP。DM 优先，私有服务器频道也支持。实时状态用“编辑同一条消息”的方式节流，不把每个内部事件刷成新消息。

### Claude 层

继续调用本机 `claude`：

```text
claude -p
  --input-format stream-json
  --output-format stream-json
  --verbose
  --include-partial-messages
  --dangerously-skip-permissions
```

Bridge 启动的子进程额外设置：

```text
DISCORD_BRIDGE_ACTIVE=1
```

其余 DeepSeek Provider/Model/Effort 全部继承用户当前环境。

### 权限层

不要试图 OCR/抓取 Claude Code 终端权限弹窗。

使用官方 `PreToolUse` Hook：每次工具调用先进入本项目的 Hook。Bridge 会话可使用 bypass permissions 提升无人值守能力，但 Hook 仍在 permission mode 前执行，所以高风险操作仍可被 deny。

Hook → `127.0.0.1` 本地审批服务 → Discord DM 按钮 → Hook 返回：

```json
{
  "hookSpecificOutput": {
    "hookEventName": "PreToolUse",
    "permissionDecision": "allow | deny"
  }
}
```

命令 Hook 必须 fail-closed：本地审批服务连不上时返回 deny。

## 风险策略

自动允许：

- 只读工具。
- 当前项目目录内普通写入。
- `git status/diff/log/show`。
- 常规 test/lint/build。

手机确认：

- `git push`、`git reset --hard`、`git clean`、rebase。
- 删除/递归删除。
- 网络访问、包安装、publish。
- 工作区外写入。
- `.env`、credentials、SSH/AWS/GitHub 凭据等敏感文件。
- 未识别工具/MCP 写操作。

后续根据实际误报率调整，不一开始堆复杂规则。

## Codex Phase 2

只有 V1 真实闭环通过后再做。

目标不是“每次都多模型协作”，而是**升级通道**：

```text
DeepSeek 正常执行
      ↓ 明确失败/用户要求
[升级 Codex]
      ↓
Codex Plus 本地登录会话
```

优先复用成熟项目的 Codex app-server / Discord approval 设计，不从零逆向 Codex。需要保持当前 cwd、任务目标、失败信息、git diff、测试结果，handoff 要短，不重复整段历史。

## ChatGPT 在线 Phase 3

不接非官方浏览器自动化。实现 `!handoff`：生成一份尽量短的文本，包含：

- 真实目标
- 当前项目/cwd
- 已完成内容
- 当前错误/瓶颈
- 关键 diff/文件列表
- 已跑测试及结果
- 希望 ChatGPT 回答的具体问题

用户把它粘贴到 ChatGPT；ChatGPT 输出新的任务指令后，再发回 Discord 给 DeepSeek 执行。

## 工程规则

- 先复用现有代码与官方 Hook，不推翻架构。
- 优先最低复杂度，不为了“多 Agent”增加无意义中间层。
- 每个改动真实运行；核心链路必须 smoke test。
- 详细开发记录、调试日志、handoff 写入仓库文件/commit，不在聊天窗口大量复述。
- 不修改用户现有 DeepSeek Provider 配置，除非实测证明兼容失败。
- 不自动启用 Codex 消耗 Plus 额度。
- 不自动执行 `git push --force`、删除用户数据、改系统级关键配置。

## 第一轮执行顺序

1. 在 Windows 解压/clone 本项目并 `npm install`。
2. 填写 `.env` 中 Discord Token、Owner ID、默认 cwd。
3. 执行 `scripts/install-global-hook.ps1`。
4. 执行现有 `npm test`，不得先跳过测试。
5. 启动 Bridge，先用 disposable repo 做真实 smoke test。
6. 验证 DeepSeek 实际执行者仍然是现有 `deepseek-flash[1m]`。
7. 验证实时工具进度。
8. 故意让 Agent 执行 `git push` 或一个无害但命中审批规则的命令，确认手机按钮确实阻塞/放行原 tool call。
9. 验证 Deny。
10. 再绑定一个真实项目测试普通 edit + test。
11. 把真实 Windows 测试结果、发现的兼容问题和修复写入仓库 `docs/WINDOWS_SMOKE.md`。
12. V1 通过后才评估 Codex adapter。
